    Etapa 1 : Tão Sonhada API¶

    Explicação Do Projeto:¶

    Neste projeto, desenvolvemos uma API que permite registrar usuários em um banco de dados, realizar o login desses usuários e consultar a cotação entre Dólar e Euro utilizando a chave gerada para cada usuário.

    Ao cadastrar um usuário, uma chave única é gerada, e essa mesma chave é retornada também no momento do login. Caso o usuário já esteja registrado no banco de dados, um novo cadastro não será realizado.

    Passo a Passo para a Aplicação Do Projeto:¶

    Para a API funcionar perfeitamente, siga os passos a passos abaixo:

    Primeira parte: Ambiente Python¶

    • Acesse o terminal e navegue até a pasta api do projeto:

    • bash cd api

    • Crie um ambiente virtual Python:

    • bash python -m venv .venv

    • Ative o ambiente virtual:

    • No Windows (PowerShell):

      • bash .\.venv\Scripts\Activate.ps1

    • No Linux/macOS:

      • bash source .venv/bin/activate

    Segunda parte: Arquivo .env¶

    • Dentro da pasta api, crie um arquivo .env com as credenciais do banco:

    POSTGRES_USER=seu_usuario POSTGRES_PASSWORD=sua_senha POSTGRES_DB=nome_do_banco

    • Adicione a chave da API do Alpha Vantage ao arquivo .env:

    • Arquivo .env:

      ALPHA_VANTAGE_API_KEY=seu_token_alpha_vantage

    Certifique-se de que a chave da API está correta para que a requisição de cotação funcione corretamente.

    Substitua os valores conforme necessário.

    Terceira parte: Instalar dependências da aplicação¶

    • Com o ambiente virtual ativo, instale os pacotes:
    • bash pip install -r requirements.txt

    Quarta parte: Subir os containers¶

    • Na raiz do projeto (onde está o compose.yaml, que está em Projeto_Cloud/api), rode:
    • bash docker compose up

    Quinta parte: Acessar a API¶

    • Acesse os seguintes endereços no navegador:
    • Página principal: http://localhost:8080
    • Swagger Docs: http://localhost:8080/docs

    Agora sua API está pronta para rodar!

    Sexta parte (opcional): Testar os endpoints¶

    • Use uma das ferramentas abaixo:
    • Postman
    • Insomnia
    • Ou via terminal com curl

    Testando Cada Endpoint e sua passo a passo.¶

    Para testar as requisições, **utilize o http://localhost:8080/docs **

    Primeira parte: Registrar um novo usuário¶

    • Envie uma requisição POST para o endpoint /registrar para cadastrar um novo usuário:

    • URL: /registrar

    • Body:

      {
  "email": "usuario@exemplo.com",
  "nome": "Nome do Usuário",
  "senha": "sua_senha"
}
      * Resposta Esperada:

      {
  "jwt": "<token_de_autenticacao>"
}

    Se o email já estiver registrado, a API retornará o código de status 409 Conflict com a mensagem Email already registered.

    Segunda parte: Realizar login¶

    • Envie uma requisição POST para o endpoint /login para realizar o login do usuário:

    • URL: /login

    • Body:

      {
  "email": "usuario@exemplo.com",
  "senha": "sua_senha"
}
      * Resposta Esperada:

      {
  "jwt": "<token_de_autenticacao>"
}

    Se as credenciais estiverem incorretas, a API retornará o código de status 401 Unauthorized com a mensagem Invalid credentials.

    Terceira parte: Consultar a cotação do Euro para Dólar¶

    • Envie uma requisição GET para o endpoint /consultar para obter a cotação de Euro (EUR) para Dólar (USD):

    • URL: /consultar

    • Cabeçalho:

      Authorization: Bearer <seu_token_jwt>
      * Resposta Esperada:

      {
  "from_currency": "EUR",
  "to_currency": "USD",
  "rate": "1.07320000",
  "last_updated": "2025-05-13 12:00:00"
}

    O token JWT gerado durante o login deve ser incluído no cabeçalho da requisição com a chave Authorization.

    Quarta parte: Testar os endpoints¶

    • Utilize uma das ferramentas abaixo para testar os endpoints:

    • Postman

    • Insomnia

    • Ou via terminal com curl:

      • Exemplo para login:
      curl -X 'POST' 'http://localhost:8080/login' -H 'Content-Type: application/json' -d '{
    "email": "usuario@exemplo.com",
    "senha": "sua_senha"
  }'

    Agora você tem o passo a passo em formato que pode ser copiado e colado diretamente!

    Screenshots das aplicações funcionando:¶

    Registrando um usuário:¶

    • Requisição com dados válidos:

    • Resultado: usuário registrado com sucesso e token JWT retornado.

    • Requisição com email já registrado:

    • Resultado: erro 409 com mensagem Email already registered.

    Realizando login:¶

    • Requisição com credenciais corretas:

    • Resultado: login bem-sucedido e token JWT retornado.

    • Requisição com credenciais incorretas:

    • Resultado: erro 401 com mensagem Invalid credentials.

    Consultando cotação do Euro:¶

    • Requisição com token válido:

    • Resultado: cotação do Euro para Dólar retornada com sucesso.

    • Requisição sem token ou com token inválido:

    • Resultado: erro 401 indicando ausência ou invalidez do token.
